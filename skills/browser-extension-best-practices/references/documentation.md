# README 与 Agent 文档

用于调整项目入口文档、贡献流程与 Agent 上下文。按 [主文档](guide.md) 确认读者与任务，只保留能指导下一步行动的信息。

## README

### 来源实现

来源项目的根 README 面向产品使用者：首屏说明产品定位，提供演示、浏览器安装入口和功能说明，并链接网站教程、更新日志、社区与贡献指南。其他语言版本位于 `readmes/`，通过相互链接切换；徽章与图片使用引用链接统一维护。

开发说明主要通过外部贡献指南和架构入口继续展开；`CONTRIBUTING.md` 重点规定贡献授权，`SOURCE_CODE_REVIEW.md` 提供源码构建说明。来源项目的 Agent 规则放在独立入口，避免用户先读内部开发流程。

依据：`README.md`、`readmes/README.zh-CN.md`、`CONTRIBUTING.md`、`SOURCE_CODE_REVIEW.md`。

### 接入建议

先确定首要读者，再选择首屏内容：

| 项目类型 | 首屏重点 | 后续说明 |
| --- | --- | --- |
| 面向最终用户的应用 | 解决什么问题、演示、安装或使用入口 | 核心能力、限制、帮助、贡献 |
| 开发者库或 SDK | 安装、最小示例、兼容环境 | API、集成、版本与迁移 |
| 内部业务仓库 | 本地运行、环境准备、验证入口 | 模块边界、部署、排障与维护 |
| 多产品仓库 | 产品或包的导航及共同准备步骤 | 各子项目拥有自己的详细入口 |

产品展示、徽章数量与多语言版本按读者需求选择。开发者需要快速运行时，把最小可运行步骤放在本地可维护的位置，具体工具版本以包配置为准；链接到唯一的详细说明。

功能声明、性能数字和“免费”等承诺需要有适用范围与可维护来源。README 可以引用发布说明和产品文档，避免将营销表述当作实现证明。多语言 README 与产品 UI 国际化独立维护，明确权威版本与更新责任。

**最小重构：** 只调整首屏与首次使用路径，修正失效链接，将重复开发说明归并到一个位置。完成条件：目标读者可以找到用途、开始步骤和帮助；开发者能找到实际安装、运行、验证命令；版本、授权和能力声明有来源。

## AGENTS 与按需文档

### 来源实现

根 AGENTS.md 只保留外部服务测试跳过策略、PR 标题及 changeset 要求。`.agents/skills` 放 PR、迁移、性能、调试等任务流程；`.claude/commands` 提供命令入口；`.codex/environments` 初始化工作区，`skills-lock.json` 记录部分外部技能来源和哈希。

来源存在维护缺口：PR 流程在 Skills 和 Claude commands 中重复维护，并引用当前缺失的根 `CLAUDE.md`；添加 Provider 的命令还使用已经变化的路径和映射名称。目录存在只能证明材料可用，具体客户端是否发现并加载需要验证。

依据：`AGENTS.md`、`.agents/skills/create-pr/SKILL.md`、`.claude/commands/add-provider.md`、`skills-lock.json`。

### 接入建议

根 Agent 文档保留每次任务都需要的业务不变量、重要操作约束和清晰指针。任务特有规则与其定义、例子、失败处理放在同一专题；客户端命令只转发到权威流程。包配置、目录或 `--help` 一次即可查到的事实，优先从环境读取。

为指针写清触发条件。目标仓库不需要复制本指南。在已有 Agent 入口添加一行，指向 `browser-extension-best-practices`：

```markdown
在评估浏览器插件的基础设施接入、版本发布或配置迁移时，使用 browser-extension-best-practices，只采用与当前问题和仓库约束匹配的做法。
```

指针连接到本技能，再按问题读取专题，避免每次任务加载全部资料。

步骤要有可判断的完成条件。例如“检查配置迁移”改为“列出全部读写入口，验证未来版本、单步失败、历史配置和写入中断的处理”。后者让 Agent 能判断调查是否完整。

**最小接入：** 一个现有 Agent 入口指针加一份权威流程。完成条件：引用均可达、适用客户端能发现入口、规则只维护一份、业务约束没有被来源项目的工具偏好覆盖。

## 文档维护

| 信息 | 权威位置 | 需要更新的触发条件 |
| --- | --- | --- |
| 依赖、脚本、环境版本 | 包配置和工具配置 | 安装、运行或验证入口变化 |
| 产品能力与使用方法 | README 与产品文档 | 用户可见行为变化 |
| Agent 操作约束 | 实际会加载的入口与任务专题 | 流程、数据边界或任务分支变化 |
| 发布政策 | 发布规范与 CI | 发布单元、版本语义或渠道变化 |
| 历史迁移规则 | 版本化脚本及历史测试样本 | 新增兼容边界；历史缺陷通常追加修复迁移 |

来源的 `SOURCE_CODE_REVIEW.md` 所列 Node/pnpm 版本已落后于其 package.json，说明手工缓存易发现配置会增加漂移成本。目标项目应保存原因、契约和排障要点，将版本与命令留给权威配置或生成流程。

交付前检查标题和指针能否准确引导任务，删除重复或过时规则，验证文件与章节链接。只报告实际完成的检查；源码归纳、自动测试与人工运行分别说明。
