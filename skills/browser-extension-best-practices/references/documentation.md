# README 与 Agent 文档

按 [优化流程](guide.md) 确定读者与任务，把原因、契约和操作边界留在文档，将版本与命令指向权威配置。

## README 与开发入口

浏览器扩展的根 README 优先回答用途、核心交互、安装和帮助。区分商店安装、发布 ZIP 和开发加载；标明支持的浏览器、必要权限用途及已知限制。功能与发布状态应有当前证据，计划中的能力单独标注。

开发入口提供最小安装、开发、构建、测试及加载扩展的路径，具体命令从项目脚本核对。贡献规则、发布流程、商店素材与源码审查说明按实际需要链接到唯一位置。多语言 README 与 UI 国际化独立维护，定义同步责任。

**完成条件：** 用户能找到安装与帮助，开发者能按说明运行并验证；本地加载、Release 下载和商店公开状态各有明确含义，链接均可达。

## Agent 入口与按需文档

根 AGENTS.md 保留常用业务不变量、重要操作约束与触发指针。任务细节与例子放在相应专题，客户端命令转发到权威流程。

需要接入本技能时，在项目已使用的 Agent 入口增加指针：

```markdown
优化浏览器插件的状态、UI、国际化、通信、测试、版本发布或配置升级时，使用 browser-extension-best-practices，按当前问题选择推荐库和最小改动，并验证运行边界。
```

具体框架 API 可由可用的专项技能或官方文档补充；本技能负责优化决策和验收，避免重复维护底层 API 手册。确认使用的客户端能发现指针及其目标。

操作规则写出完成条件。例如配置升级要列出全部入口并验证历史数据、未来版本与写入中断；发布检查要核对版本、提交、产物与渠道状态。内部代码简化规则应明确适用范围，用户持久数据的保留或重置另有契约。

## 权威位置与维护时机

| 信息 | 权威位置 | 更新触发 |
| --- | --- | --- |
| 依赖、运行时版本、命令 | 包配置、锁文件与工具配置 | 安装、构建或检查方式变化 |
| 产品能力、权限说明、使用方式 | README、帮助与商店材料 | 用户可见行为或权限变化 |
| Agent 工作约束 | 实际加载的入口与任务专题 | 操作边界或任务分支变化 |
| 版本政策与发布流程 | 发布文档和 CI | 发布单元、升级级别、触发策略或渠道变化 |
| 历史数据兼容 | 迁移脚本、固定历史样本与契约 | 数据格式或支持范围变化 |

**交付检查：** 指针与标题准确，文件及章节链接可达，重复规则已归并，命令与配置一致。记录实际验证结果；临时调试记录不必进入长期使用文档。
