# 浏览器插件优化流程

围绕可观察的问题优化一个业务场景。先明确浏览器、扩展入口、用户数据和发布渠道，再选择工具与改动边界。

## 问题分诊

| 症状或任务 | 首先调查 | 专题 |
| --- | --- | --- |
| 选型、入口耦合、依赖重复 | 现有框架、运行环境与模块依赖 | [架构与界面](architecture-and-ui.md) |
| 设置不同步、快速操作丢失、重复渲染 | 数据所有者、全部写入者、订阅与竞争顺序 | [状态管理](architecture-and-ui.md#状态管理) |
| 控件行为不一致、宿主网页影响 UI | 组件原语、Token、Shadow DOM 与 Portal 容器 | [组件与样式](architecture-and-ui.md#组件与样式) |
| 多语言、语言切换、manifest 文案 | 浏览器语言与应用语言需求、资源生成与回退 | [国际化](architecture-and-ui.md#国际化) |
| iframe 漏响应、指令乱序、后台唤醒后失效 | 消息身份、路由、队列作用域和恢复路径 | [通信与生命周期](architecture-and-ui.md#通信与生命周期) |
| 本地通过但安装失败、CI 漏检 | 源码测试、实际产物和浏览器验收各自覆盖范围 | [工程质量](quality-and-evolution.md#工程质量) |
| 版本混乱、Release 缺附件、商店提交 | 版本来源、Changesets、版本 PR、产物及渠道状态 | [完整发布流程](quality-and-evolution.md#完整发布流程) |
| 更新后设置丢失、导入旧配置失败 | 已发布数据格式、升级入口与恢复契约 | [配置升级](quality-and-evolution.md#配置升级) |
| 开发说明重复、Agent 找不到规则 | 读者、权威位置和触发指针 | [文档](documentation.md) |

## 工作步骤

1. **定位调用链。** 读取仓库规范、依赖、构建配置与相关代码；追踪入口、消息、业务规则、状态读写和副作用。完成条件：能列出真实路径、目标浏览器和数据所有者，缺失证据单独标明。
2. **确定问题与基线。** 写清触发条件、当前行为、期望结果和需要保护的交互或数据。性能问题记录可比较的测量；架构偏好单独作为选型需求。完成条件：有可观察的验收标准。
3. **选择方案。** 按下表选择保留、接入、局部重构或暂缓；缺失能力优先采用专题中的推荐库，已有实现比较职责与迁移成本。完成条件：每个新增依赖都有调用方和具体收益。
4. **实施一个纵向场景。** 列出入口、调用方、写入者、持久格式及必要的恢复方式，沿真实入口接通。完成条件：相关调用方全部更新，业务状态权威来源明确，临时兼容路径有删除条件。
5. **验证并交接。** 执行与风险匹配的源码、产物和浏览器检查，更新唯一维护位置。完成条件：分别报告已验证行为、未验证范围及失败恢复方式。

| 判断 | 决策 |
| --- | --- |
| 现有能力满足需求，无具体缺陷或重复维护 | 保留，记录有效边界 |
| 能力缺失，有稳定接入点 | 接入推荐能力，先完成一个场景 |
| 同一规则重复，或边界导致可复现错误 | 局部重构，共享规则并收敛所有权 |
| 收益、目标行为或环境尚不明确 | 暂缓相关改动，先补证据 |

用户只要求分析时，完成决策即可；已要求实现时，继续执行已明确的范围，无需要求用户再次选择同一方案。

## 交付内容

| 字段 | 必须说明 |
| --- | --- |
| 问题与证据 | 触发场景、调用路径、基线或复现 |
| 推荐与取舍 | 具体库或机制、保留或替换理由、维护成本 |
| 边界与改动 | 状态所有者、读写入口、调用方、持久格式 |
| 验收与结果 | 实际执行的检查、用户可见行为、未覆盖环境 |
| 恢复与收尾 | 数据恢复、发布重试、兼容路径删除条件及文档更新 |

发布流程任务按 [完整发布流程](quality-and-evolution.md#完整发布流程) 逐阶段给出实施或接入计划，标明未接入、未验证及需要渠道授权的环节；版本 PR 只是其中一步。

源码存在、测试覆盖和真实浏览器行为分别陈述。只检查过测试代码时，写明尚未执行；构建成功也不能代替安装、交互或商店状态证明。
