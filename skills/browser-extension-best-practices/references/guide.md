## Agent 工作步骤

1. **确认目标项目的现状。** 读取本地规范、依赖与脚本，沿一条相关业务调用链追踪入口、状态所有者、持久化和副作用。完成条件：能列出具体路径和实际约束；未验证的内容标为待验证。
2. **限定本次问题。** 写清触发条件、现有行为、期望行为及需要保护的数据或交互。完成条件：存在可观察的验收标准；架构偏好与业务缺陷分开陈述。
3. **只读取相关专题。** 为每个候选方案标记“保留现状、接入、局部重构、暂缓”，说明理由。完成条件：已有等价能力已被比较，新增依赖和维护成本有明确用途。
4. **确定最小边界。** 列出修改入口、调用方、唯一写入者和兼容方式。涉及持久数据时，确定备份、失败处理及重试策略。完成条件：一个纵向场景可以独立交付；新旧路径的分流条件明确。
5. **在已授权范围内实施。** 先完成该场景，再依据结果决定扩展；借鉴设计时使用目标项目已有工具。完成条件：新增路径可由真实入口到达，业务状态有唯一权威来源，临时兼容层有删除条件。
6. **验证并交接。** 执行与变更相称的检查，核对调用方、历史数据和可见行为。完成条件：报告实际执行结果、剩余限制与回退办法，并将稳定规则写入唯一维护位置。

仅要求分析或方案时，交付到决策与验收标准即可。目标项目缺少实现必需的信息时，先完成独立调查，再集中询问缺失条件。

## 选择接入方式

| 目标情况 | 选择 | 实施尺度 |
| --- | --- | --- |
| 已有方案能满足需求，且没有重复维护或可复现缺陷 | 保留现状 | 记录边界，补必要说明 |
| 能力缺失，新增模块可通过稳定接口接入 | 接入 | 一个业务场景、一处接入边界 |
| 多个调用方重复处理同一规则，或现有边界导致具体错误 | 局部重构 | 合并规则与所有权，逐个迁移调用方 |
| 目标行为、收益或运行环境尚不明确 | 暂缓 | 补调用链、复现或测量证据 |
| 多个入口或包已形成独立生命周期 | 评估更大拆分 | 根据依赖、交付与维护边界决定包结构 |

## 三个应用示例

**已有 React、Zustand 与 CSS Modules 的 Web 应用。** 发现主题颜色分散时，可在现有样式体系中先统一语义 CSS 变量，再调整一个按钮和表单。共享状态继续由现有 Store 管理；只有确认远程缓存需求后，再评估 Query。WXT 与 Shadow DOM 没有对应需求时无需接入。

**已有 i18n 库、需要不中断编辑地切换语言的工具。** 保留翻译资源与 API，在现有订阅机制上驱动语言更新，验证未保存草稿和编辑器实例。来源项目的语言门面可以借鉴；按 locale 重新挂载整棵业务子树可能不符合该工具的状态契约。

**需要维护用户本地配置的桌面工具。** 优先建立独立 Schema 版本、历史样本和可恢复写入，再增加迁移链。无需因为 来源项目使用 Vite glob、Jotai 或 Dexie 就引入这些依赖；注册表、存储和状态通知可以沿用目标平台机制。

## 决策交付格式

在目标项目中交付以下内容，路径与命令从该项目现场读取：

| 字段 | 必须说明的内容 |
| --- | --- |
| 问题与证据 | 触发场景、实际调用路径、当前行为 |
| 决策 | 保留、接入、局部重构或暂缓及理由 |
| 边界 | 状态所有者、写入入口、调用方和持久化格式 |
| 最小改动 | 一个可验收的纵向场景及涉及模块 |
| 验收 | 真实行为、兼容性、必要检查及结果 |
| 恢复与收尾 | 数据备份、回退方式、兼容层删除条件 |

本指南归纳源码与配置设计，没有执行 来源项目的构建、测试或浏览器验证；它不能替代目标项目的验证结果。
