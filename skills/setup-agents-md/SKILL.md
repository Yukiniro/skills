# Setup AGENTS.md

创建或更新 `AGENTS.md` 的通用工程原则章节。

## 工作流

1. 默认在用户指定的位置创建或更新 `AGENTS.md`；未指定时写入当前仓库根目录。
2. 文件不存在时，创建 `# AGENTS.md` 标题和下方完整的工程原则章节。
3. 文件已存在时，保留原始内容。仅更新已有的工程原则章节；若不存在该章节，则在文件末尾新增 `## 工程原则`。
4. 将中文或英文的同义工程原则章节合并为一节，并用下方规则替换该节内容。不要修改其他章节。
5. 新增或更新的工程原则使用中文，保持原始内容的语言和文字不变。

## 工程原则

每个新增或更新的工程原则章节必须包含以下规则：

- 不保留向后兼容性。删除过时路径；不添加兼容层、回退逻辑或迁移方案。
- 选择完整满足当前需求的最简单实现；避免投机性的抽象、配置和间接层。
- 分层演进。先交付端到端可用的最小版本，再在可用产品上逐项增加能力；不要用未完成的复杂性替换可用产品。
- 保持组件模块化并清晰分离关注点。
- 成熟且维护良好的库能降低复杂度或提升可靠性时优先使用；没有明确理由不得重造常见功能。
- 写实现或新增依赖前，先检查和利用已有依赖；查阅文档和类型后再判断其能力。
- 以长期架构决策为准；不要接受只能暂时工作、注定日后替换的权宜方案。
